# 功能规格 · 图文笔记社区与笔记搜索

| 功能编号 | 创建日期 | 状态 | 需求来源 |
| --- | --- | --- | --- |
| `001-note-community-search` | 2026-11-21 | 草案，可进入技术规划 | [第一版 PRD](../../PRD.md) |

第一版涵盖账号、图文笔记、首页、收藏和笔记搜索。开发者与同学在本地使用同一批示例数据验收。面试时应能解释一次笔记修改如何反映到搜索结果，以及搜索中断时为什么仍能保存笔记。

## 用户场景与测试

以下四个故事均须交付。P1 是发布、查找与故障恢复的核心流程，P2 补齐个人收藏。每个故事可以从自己的预置数据开始验收。

### US1 · 发布笔记，让另一位读者看到（P1）

**独立验收。** 提供作者甲、读者乙两个账号和一篇较早发布的笔记，分别登录两个会话。

| 操作 | 预期结果 |
| --- | --- |
| 甲填写标题、正文，选择一张本地图片并发布。乙刷新首页，点击第一张卡片 | 新笔记排在旧笔记之前。卡片能看见封面和标题，详情展示甲刚保存的图文 |
| 乙尝试修改或删除甲的笔记，包括直接提交相应请求 | 两次操作均遭拒绝。甲仍能打开原笔记，内容完整 |
| 甲修改标题并保存，随后删除笔记 | 保存成功后重新打开详情即见新标题。删除成功后，乙通过原链接无法再读取内容，刷新首页后卡片消失 |
| 甲退出，再尝试以甲的身份发布笔记 | 系统要求登录，这次操作不会产生新笔记 |

### US2 · 按中文关键词找回笔记（P1）

**独立验收。** 预置两篇已可检索的笔记。A 的标题为《美团一面复盘》，正文为“记录面试中的数据库问题”。B 的标题为《周末面试笔记》，正文为“整理美团面试问题”。两篇各有一张配图。

| 操作 | 预期结果 |
| --- | --- |
| 乙搜索“美团”，点击第一条结果 | A、B 各出现一次，A 排在 B 前面。点击后打开 A 的详情 |
| 甲将 A 改名为《字节一面复盘》，保留正文，再分别搜索“美团”和“字节” | 详情立即显示新标题。同步完成后，“美团”只命中 B，“字节”只命中 A |
| 搜索服务可用时，乙查询两篇笔记都不含的词“火山” | 页面显示“没有找到相关笔记” |

### US3 · 搜索中断时继续写，恢复后能搜到最新内容（P1）

**独立验收。** 准备两个账号、一篇已经可以搜到的笔记，以及可单独暂停、恢复的搜索服务。编辑使用不同标题，且正文不含这些标题词。允许测试主动重放指定的历史更新。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 搜索故障 | 先确认搜索“火山”显示“没有找到相关笔记”。暂停搜索服务，再查“火山”和一个原本能命中的词。甲同时发布一篇新笔记，先后改名两次 | 停服后的两次查询均提示“搜索暂时不可用，请稍后再试”。甲仍能保存，乙刷新首页并打开详情能看到最终标题。日志或测试记录显示，搜索故障未触发主数据库代查 |
| 编辑任务晚到 | 恢复服务，等新笔记能按最终标题搜到，再把第一次改名的更新重放两次，等待处理完成 | 无需甲再次保存。按最终标题仍只命中这篇笔记一次，按初始和中间标题均找不到它 |
| 删除后重试 | 另取已被收录的笔记。停搜索、改标题、删笔记，再恢复搜索。等搜索中已查不到它后，重放删除前的改名更新并等待处理完成 | 从删除成功起，原详情就无法读取。重放结束后，用删除前的新旧标题查询，结果都不含这篇笔记 |

### US4 · 收藏笔记，稍后从个人页找回（P2）

**独立验收。** 预置甲发布的一篇笔记，甲乙两人的收藏列表初始都为空。

| 操作 | 预期结果 |
| --- | --- |
| 乙在两个页面同时收藏该笔记，再刷新收藏页 | 乙的列表仅有一条记录，点击可打开原笔记。甲的列表仍为空 |
| 乙取消收藏、刷新，再次收藏。甲随后删除原笔记 | 取消后列表为空。再次收藏后有一条，删除原笔记并刷新后该条消失 |

## 功能要求

| 编号 | 可观察行为 |
| --- | --- |
| FR-001 | 两个预置账号可独立登录、退出。系统根据当前登录身份确定作者及个人收藏的归属 |
| FR-002 | 登录用户可发布带标题、正文和图片的笔记。只有作者能编辑或删除。详情读取最近一次成功保存的内容 |
| FR-003 | 首页用双列图文卡片按发布时间倒序展示笔记。卡片可打开详情。删除的笔记在下次刷新首页时移除 |
| FR-004 | 登录用户可收藏、取消收藏和查看个人收藏。同一用户与同一笔记最多形成一条收藏记录 |
| FR-005 | 中文关键词匹配标题和正文。标题命中排在仅正文命中之前，同一笔记在结果中最多出现一次 |
| FR-006 | 查询成功且零匹配、搜索服务不可用是两个可区分的结果，分别显示 US2、US3 指定的提示 |
| FR-007 | 搜索故障期间仍可发布、编辑、删除和浏览笔记，系统不向主数据库发起替代性的笔记搜索查询 |
| FR-008 | 搜索恢复后自动反映笔记最终状态。重复处理或乱序处理历史更新均不能盖过后来的编辑，也不能让已删笔记重新出现 |

### 核心实体

- **账号**拥有自己发布的笔记和收藏列表。
- **笔记**包含作者、标题、正文、图片和发布时间。同一笔记改名后仍能通过原链接打开，直至作者删除它。
- **收藏**关联一个账号和一篇笔记。取消收藏只影响执行操作的账号。
- **搜索结果**指向原笔记。编辑后允许短暂显示旧标题，即使旧结果暂时可见，也不能借此打开已经删除的内容。

## 成功标准

| 编号 | 交付时如何判定 |
| --- | --- |
| SC-001 | 按本地启动说明，用两个示例账号能走完发布、首页浏览、搜索、收藏和取消收藏的流程，并复现 US1 的权限检查 |
| SC-002 | US2 和 US3 的场景均有可重复运行的自动化测试。查询结果可区分有匹配、零匹配和服务故障。恢复、重复及乱序重试后的结果与表中预期一致 |
| SC-003 | 技术方案选定一个本地同步等待上限并写入测试配置。正常变更从保存成功起计时，故障恢复从服务重新可用起计时。测试记录实际耗时，超过上限即失败 |
| SC-004 | 接手者能用交付的架构图追踪一次改名，再按步骤复现 US3。随附的一页取舍说明能结合实现解释何时直接查库已足够、独立索引增加了什么成本，以及失败的更新如何被发现和补上 |

## 范围与约定

验收使用预置账号以及可重复装载的示例图文。首页与发布页可参考 PRD 中给出的 Vue 历史页面，页面行为以本规格为准。后端沿用 PRD 的 Python 和 FastAPI 方向。数据库、搜索引擎、同步机制和本地等待上限由技术方案确定。
